# 恒温恒湿控制系统 —— 接线说明

主控：**STM32F103C8T6 最小系统板**（LQFP48）

本项目所有外设都接在**一块开发板**上，共占用 25 个 GPIO，无需第二块板协同。

---

## 一、关于 5V 容忍引脚（重要）

STM32F103 上带 ADC 功能的引脚 —— **PA0~PA7、PB0、PB1** —— **不是 5V 容忍的**，
接入 5V 信号会损坏引脚；其余 IO（PA8~PA15、PB2~PB15）都是 5V 容忍（FT）引脚。

本项目的编码器按题目要求用 **5V 供电**，它的 S1/S2/KEY 输出高电平就是 5V，
因此**六个编码器信号全部安排在 FT 引脚上**；
而继电器、蜂鸣器、加湿器这些是**单片机往外输出**，不存在被 5V 灌入的问题，
所以把它们放到非 FT 的 PA1~PA3 上，把 FT 引脚让给编码器。

制冷片旁的冷风风扇改用 PWM 调速后，信号线特意放在 **PB9**：既是硬件定时器
通道（TIM4_CH4，波形由硬件产生，不受中断影响），又是 5V 容忍引脚 ——
4 线 PWM 风扇的调速线在风扇内部被上拉到 5V，接在非 FT 引脚上有损坏风险。

## 三、分模块接线

### 1. DHT11 温湿度传感器

| DHT11 | STM32 |
|---|---|
| VCC | 3.3V |
| DATA | **PA0** |
| GND | GND |

DATA 与 3.3V 之间接 **4.7kΩ 上拉电阻**（多数现成模块板上已自带，自带的不用再加）。

### 2. OLED 显示屏（0.96 寸，SPI 接口，7 针）

| OLED | STM32 |
|---|---|
| GND | GND |
| VCC | 3.3V |
| D0 / SCL / CLK | **PB13** |
| D1 / SDA / MOSI | **PB15** |
| RES | **PB14** |
| DC | **PB8** |
| CS | **PB12** |

> 屏幕丝印命名不统一：D0=SCL=CLK 是时钟，D1=SDA=MOSI 是数据，按功能对应即可。

### 3. RFID-RC522 刷卡模块

| RC522 | STM32 |
|---|---|
| VCC | **3.3V**（切勿接 5V，模块为 3.3V 供电） |
| RST | **PB0** |
| GND | GND |
| IRQ | 悬空不接 |
| MISO | **PA6** |
| MOSI | **PA7** |
| SCK | **PA5** |
| SDA (NSS/CS) | **PA4** |

### 4. 旋钮编码器 ×2（EC11 类，5V 供电）

| 编码器 | 引脚 | STM32 |
|---|---|---|
| 编码器1（调**温度**） | S1 | **PB5** |
| | S2 | **PB6** |
| | KEY | **PB7** |
| | VCC / GND | 5V / GND |
| 编码器2（调**湿度**） | S1 | **PB10** |
| | S2 | **PB11** |
| | KEY | **PA8** |
| | VCC / GND | 5V / GND |

> 这 6 个引脚都是 5V 容忍引脚，编码器按 5V 供电可以直接接，无需电平转换。
> 若你的编码器模块支持 3.3V 供电，接 3.3V 同样可以工作。
>
> 若实际旋转方向与预期相反，把该路的 **S1 与 S2 两根线对调**即可，不用改代码。

### 5. 继电器模块（除湿风扇 / 加热器 / 制冷片）

推荐用带光耦隔离的继电器模块：

| 继电器模块 | STM32 |
|---|---|
| VCC | 5V |
| GND | GND |
| IN1（除湿风扇） | **PA1** |
| IN2（加热器） | **PA2** |
| IN3（制冷片） | **PA3** |

强电/大电流侧：除湿风扇、加热器、制冷片各自的电源经继电器**常开触点（NO）**串联接入。

> 代码默认继电器为**高电平吸合**（`RELAY_ACTIVE_LOW = 0`）。若你的模块是低电平吸合，
> 只需把 `HARDWARE/ACTUATOR/actuator.h` 里的 `RELAY_ACTIVE_LOW` 改成 `1`。
>
> 这一路的风扇是湿度控制用的（湿度高于设定值 + 回差时吸合除湿），只有开/关两种状态；
> 制冷片旁边那台按温差调速的风扇是**另一台**，见第 8 节。

### 6. 加湿器

| 加湿器 | STM32 |
|---|---|
| 控制脚 | **PA12**（高电平开启） |
| GND | 与主控**共地** |

> 若加湿器需要的驱动电流较大，PA12 不要直驱，中间加一级 NPN 三极管
> （如 S8050）或 MOS 管；若加湿器工作电压是 5V 以上，同样建议经三极管驱动。

### 7. 蜂鸣器

| 蜂鸣器 | STM32 |
|---|---|
| 正极 / I/O | **PA11**（高电平响） |
| GND | GND |

> 使用**有源蜂鸣器**（自带振荡电路，给高电平就响）。
> 若用无源蜂鸣器，需要输出 2~4kHz 方波，本项目未做 PWM，请选有源的。

### 8. 冷风风扇（制冷片旁边的循环风扇，PWM 调速）

**注意：这台风扇和第 5 节里"湿度高时吸合"的除湿风扇是两台不同的风扇。**
这台装在制冷片上，负责把制冷片附近的冷空气吹向四周，转速由程序按温差决定。

| 冷风风扇 | STM32 |
|---|---|
| PWM / 调速线 | **PB9**（TIM4_CH4，25kHz） |
| 电源 | **独立电源**（按风扇铭牌，常见 12V），不要从开发板取电 |
| GND | 与主控**共地** |

驱动方式二选一：

1. **4 线 PWM 风扇**：PWM 线直接接 PB9，风扇电源单独接 12V，GND 与主控共地。
   PB9 是 5V 容忍引脚，能承受风扇内部对调速线的 5V 上拉。
2. **2 线风扇 + MOS 管/三极管**：PB9 接栅极/基极，风扇串在管子漏极/集电极与
   电源之间，用 PB9 输出的 PWM 斩波调速；风扇是感性负载，需并联续流二极管。

占空比由程序按"室温 - 目标温度"自动给出，无需人工干预：

| 室温 − 目标温度 | 冷风风扇占空比 |
|---|---|
| ≤ 0℃（室温不高于目标温度） | 0%（停转） |
| 1 ~ 9℃ | 每高 1℃ 加 10%（即 10%~90%），线性 |
| ≥ 10℃ | 100%（满速） |

> 线性映射**不设转速下限**，1℃ 时只有 10%。若风扇在这个占空比下起转困难
> （多数 4 线风扇的启动门限约 20%~30%），可在
> `HARDWARE/CONTROL/control.h` 调 `COLDFAN_DUTY_PER_DT`，或在
> `control.c` 里给 `g_sys.cold_fan` 加一个下限值。
> 若遇到反相控制的风扇（占空比越小转得越快），把 `actuator.c` 里的
> `TIM_OCPolarity_High` 改成 `TIM_OCPolarity_Low`。
>
> **刷卡验证期间风扇会自动停转**：PWM 的边沿噪声会盖住 RC522 的 13.56MHz
> 射频前端，导致风扇一转起来就刷不上卡。按下编码器按键进入"等待刷卡"状态时
> 程序会把占空比置 0，验证结束（成功/失败/超时）立刻恢复原转速。
> 这段时间制冷片仍在工作，只是冷气暂时不吹开，十几秒内不影响恒温。

## 四、供电注意事项

1. **RC522 必须接 3.3V**，接 5V 会烧模块。
2. 继电器、风扇、加湿器等感性负载建议**独立 5V/12V 电源供电**，
   不要全部从开发板的 USB 取电，否则容易因瞬间电流拉低电压导致单片机复位。
   其中冷风风扇本身就是独立供电，PB9 只输出 PWM 信号，不承担风扇电流。
3. 所有电源**必须共地**，否则信号电平没有参考，控制会失效。
4. 继电器吸合瞬间的反电动势会干扰单片机，模块自带的续流二极管要确认在位。
5. 上电到程序跑起来之前的极短时间内，IO 处于浮空态，继电器可能有一次抖动，
   属正常现象；程序一进 `main` 就会把所有执行机构置为断开。

## 七、冷风风扇干扰 RC522 的排查

现象：上电时刷卡正常，冷风风扇（PWM）一转起来之后就再也读不到卡。

原因有两个，通常同时存在：

1. **辐射干扰**：25kHz PWM 的开关边沿是宽带的，谐波会落进 RC522 的
   13.56MHz 接收频段，把射频噪声底抬高，读卡距离直接从几厘米掉到零。
2. **供电跌落**：风扇启停的浪涌（以及电机换向噪声经共地线传导）会让 3.3V
   瞬间下跌，RC522 被复位后寄存器回到默认值（天线关闭、定时器配置丢失），
   此后即使干扰消失也一直读不到卡 —— 这就是"再也不识别"的原因。

程序里已经做了三件事：

| 措施 | 位置 | 作用 |
|---|---|---|
| 刷卡验证期间占空比置 0 | `control.c` 的 `ColdFan_Apply()` | 从源头去掉 PWM 干扰源 |
| PB9 输出速率降到 2MHz | `actuator.c` 的 `ColdFan_PwmInit()` | 边沿变缓，宽带谐波大幅减少 |
| 读卡前自动检查并重新初始化 RC522 | `rc522.c` 的 `RC522_Check()` | RC522 被复位后能自动恢复 |

如果换上新程序后**仍然偶尔刷不上卡**，说明干扰是通过电源/地线或空间耦合进来的，
需要从硬件上处理，按效果从大到小：

1. **RC522 单独稳压**：3.3V 就近加 **100nF + 10µF** 去耦电容，电源线尽量短；
   条件允许时用独立的 3.3V LDO 给 RC522 供电，不要和风扇共用一个 5V/3.3V 输出。
2. **地线单点汇合**：风扇电源的 GND 直接回电源负极，不要经过主控板再绕回来；
   PWM 信号地与功率地只在电源处一点相连。
3. **PWM 线远离天线**：PB9 到风扇的线尽量短、绞在一起，远离 RC522 天线区域，
   必要时串一个 **100Ω 电阻** 抑制边沿振铃。
4. **加磁珠/滤波**：风扇电源正负极套一个磁环，或在风扇电源上串磁珠。
5. **改用光耦/隔离驱动**：风扇 PWM 经 6N137 之类的高速光耦隔离，
   彻底切断地环路（隔离后风扇侧需独立供电）。
6. **拉开距离**：RC522 天线与风扇、电机本体保持 5cm 以上，中间不要有大块金属。
