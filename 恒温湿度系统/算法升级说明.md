## 卡尔曼滤波

温度和湿度分别维护估计值 x、估计方差 P，采用随机游走模型 A=H=1：

```text
P_predict = P + Q
K = P_predict / (P_predict + R)
x = x + K * (measurement - x)
P = (1 - K) * P_predict
```

首个有效读数直接初始化 x，P 初始化为 R，避免从零缓慢爬升。内部浮点计算，输出再转换为十分之一单位，避免每轮定点截断造成滤波“卡住”。

| 参数 | 温度 | 湿度 |
| --- | --- | --- |
| Q，每次采样的过程方差 | 0.04 ℃² | 0.25 (%RH)² |
| R，测量方差 | 1.0 ℃² | 4.0 (%RH)² |

参数位于 `dht11_filter.h`，按 2 秒采样起步。Q 增大或 R 减小，跟随更快、平滑更弱；反之平滑更强、滞后更大。改变采样周期后需要重新评估 Q。滤波不能校正传感器偏置，也不能把 DHT11 的测量精度提升到 0.1℃/0.1%RH。此处不再保留中值级，卡尔曼滤波本身不保证剔除所有量程内的突发异常点。

每周期只进行一次 DHT11 事务。通讯失败或整数温度不在 0～50℃、湿度不在 20～90%RH 时，立即标记无效，关闭执行器并复位 PID。下一次有效读数重新初始化滤波，不混入故障前状态。与旧工程相比，不再容忍连续三个失败周期后才停机，也不进行 50ms 间隔的快速重试。

## 模糊 PID

输入 e=设定值−测量值，ec=(e−上次e)/dt。dt 来自实际系统节拍差，单位秒，正常约 2 秒。将 e、ec 缩放并限幅到 [-3,3]，语言变量依次为 NB、NM、NS、ZO、PS、PM、PB。三个 7×7 规则表位于 `fuzzy_pid.c`：行是 e，列是 ec，元素是对应的参数修正语言值。

使用相邻三角隶属函数的乘积权重和单点后件加权平均推理；根据基础增益计算每次的修正，不把修正无限累加：

```text
Kp = clamp(Kp_base + Kp_adjust * fuzzy_kp, 0, Kp_base + Kp_adjust)
Ki = clamp(Ki_base + Ki_adjust * fuzzy_ki, 0, Ki_base + Ki_adjust)
Kd = clamp(Kd_base + Kd_adjust * fuzzy_kd, 0, Kd_base + Kd_adjust)
u  = clamp(Kp * e + integral - Kd * filtered_measurement_rate, -100, 100)
```

`fuzzy_*` 为 [-1,1] 的推理值。微分项作用于测量值，使用低通滤波；大误差时清零积分，只在积分分离范围内积分；饱和时禁止继续向饱和方向累积积分。设定值改变、传感器异常及采样超时都会清空相应历史状态。

| 参数 | 温度初值 | 湿度初值 |
| --- | --- | --- |
| Kp / Ki / Kd | 12 / 0.08 / 3 | 6 / 0.04 / 1 |
| Kp / Ki / Kd 最大修正幅度 | 6 / 0.06 / 2 | 3 / 0.03 / 0.8 |
| 对应模糊 ±3 的误差 | ±5℃ | ±10%RH |
| 对应模糊 ±3 的误差变化率 | ±0.5℃/s | ±1%RH/s |
| 积分分离范围 | ±3℃ | ±6%RH |
| 微分滤波时间常数 | 4s | 4s |

误差和变化率范围必须为正数，所有增益和时间常数应为非负数。温湿度两个回路独立运算，未加入温湿耦合补偿；共同运行后的效果需要实测。

## 继电器如何执行 PID 输出

| 回路输出 | 正值 | 负值 |
| --- | --- | --- |
| 温度 | 加热器 | 制冷片 |
| 湿度 | 加湿器 | 除湿风扇 |

绝对值表示 0～100% 的需求功率，不能直接作为机械继电器的高频 PWM。现使用 **60 秒时间窗口**，例如稳定的 +30% 温度需求对应每窗口约 18 秒加热，其余时间关闭。窗口内锁存幅度，到下个窗口更新；方向改变或变成零时提前处理，但正常切换仍需满足最短开启时间。

- 最短开启 5 秒、最短关闭 5 秒、相反方向切换前停机至少 5 秒。
- 启动、恢复或换向的最短关闭等待可能缩短该窗口的脉冲；最短开启约束可能延后正常关闭。实际通电时间以这些约束优先。
- 小于 5 秒的请求脉冲直接舍弃。因此 60 秒窗口的最小非零请求约为 8.33%，不能输出任意细小的连续功率；积分可能逐渐累积到可执行脉冲。
- 非满功率但关闭时间小于 5 秒的请求限制为 55 秒开启；100% 允许持续开启。
- 两组正反执行器分别互锁，GPIO 写入时先关旧方向，再开新方向。
- 故障停机立即执行，优先于最短开启约束；恢复后仍遵守最短关闭时间。

冷风风扇仅在制冷继电器实际开启时转动，PWM 占空比取制冷需求，最低 30%。刷卡等待期间沿用原工程的暂停风扇逻辑。若风扇承担制冷片热端散热，应先按实际散热结构重新确认这项刷卡暂停策略，不能把散热要求套用为普通冷风循环风扇。

这些时间参数必须与实际继电器和负载要求核对。当前按工程里的制冷片设计；如实际换成压缩机，必须按设备要求增大停机/重启时间。除湿风扇依靠换气工作，环境空气更湿时无法单靠风扇实现降湿，算法无法补足执行器能力。

超过 6 秒没有新控制采样时，`Control_ApplyOutputs()` 关闭全部执行器。该检查依赖主循环继续运行，不是硬件看门狗，无法覆盖整个主循环卡死的情况。

## 编译、观测和整定

1. 使用 Keil MDK5 打开 `USER/TempHumi.uvprojx`，选择 `TempHumi`，执行 Rebuild。新增文件已登记到工程，原 include 路径可直接使用。
2. 先核对 `RELAY_ACTIVE_LOW` 和输出极性；通过现有 9600 波特串口查看数据，确认断开 DHT11 后输出归零、恢复后不立即绕过最短关闭保护。
3. 先单独调温度回路，再单独调湿度回路。记录设定值、原始/滤波读数、PID 需求与实际继电器状态。原始读数可在 `DHT11_Filter_Update()` 的 t/h 变量处观察，或调试时另加串口输出。
4. 初期可将 Ki、Kd 及三个修正幅度设为 0，整定基础 Kp；随后逐步增加 Ki 消除稳态偏差，再按需要加入 Kd 和模糊修正。每次改变一类参数，保留完整响应曲线。
5. 滤波延迟、60 秒窗口与执行器惯性会叠加影响超调。根据实际响应调整 Q/R、窗口和增益，再联合测试温湿度回路。不要用更激进的增益补偿过强滤波。

新增串口字段 `UT10`、`UH10` 是有符号 PID 需求×10，例如 `UT10=-325` 表示请求 32.5% 制冷；`V=0` 表示本次传感器数据无效。`HT/CL/FN/HM` 仍是实际开关状态，`CF` 是冷风风扇需求占空比（刷卡期间物理输出强制为零）。可在调试器查看 `s_temp_pid`、`s_humi_pid` 的实时 Kp/Ki/Kd。
